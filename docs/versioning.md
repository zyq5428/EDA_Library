# 版本、备份与项目复现

## 日常修改

1. 在关闭相关 Cadence 编辑器后，检查当前 Git 状态并拉取更新。
2. 完成一个器件的修改、模型生成和验证，同步 CSV 与检查记录。
3. 运行 `python scripts/validate_library.py`。
4. 检查 `git diff` 与暂存内容，特别是二进制模型、第三方文件与机器配置。
5. 将 `.dra/.psm`、依赖 `.pad`、`.olb`、清单和记录作为同一次器件变更提交。

提交说明示例：`feat: add IC-0001 with reviewed symbol and footprint`。不要让多人同时修改同一个二进制 `.olb`；Git 无法像代码一样可靠合并这类文件。

## 变更规则

- 文档和参数纠错：记录修改依据，不自动改动已有 PCB。
- 焊盘尺寸、孔、编号或封装几何变化：创建新模型名/修订，保留原文件；受影响的器件重新检查。
- 废弃件标为 `deprecated`，不要删除历史项目所需的模型。
- 更改全局库不意味着已存在的设计自动更新；在 Cadence 中显式更新并重新检查网表和布局。

## 项目冻结

打样时在项目仓库登记本库 commit SHA 或 tag，例如 `library-2026-10-11`，并保存项目实际使用的符号与物理模型快照。

从 PCB 导出的封装只覆盖该板所用模型，不等于原理图符号完整备份。快照应包含原理图库、封装、焊盘和需要的 STEP。项目冻结模型的搜索路径优先于个人最新库，避免同名覆盖。

## Git 与云端

Git 是本仓库文件与记录的版本依据；Cloud Workspace 是云端器件发布与修订依据。两者不自动同步，检查记录中登记对应修订。

GitHub 之外保留定期本地备份。此框架未自动启用 Git LFS；开始积累大量二进制资料前，可按文件体积、托管配额和使用习惯决定是否启用。
